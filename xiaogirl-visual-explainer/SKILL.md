# 小女孩 PPT Skills

这是一个可跨网页、PPT、推文和视频分镜复用的赛事女孩视觉 Skill。默认角色是模拟投资大赛的小女孩 IP；默认画风是白底黑色手绘线稿、深蓝与青色识别色、少量红橙蓝批注。线上白皮书中的 12 张 girl-ip 成品是当前风格母版，优先以其笔触、构图密度和角色比例为准。

## 适用输出

- **网页**：生成 16:9 正文解析图，或 9:16 手机长图/今日战报，并按章节、模块或文字锚点插入 HTML；需要时提供可留白的页面场景底图。
- **PPT**：按页面主题生成单页视觉图、概念图、流程图或角色动作图；官方 Logo、日期、奖项、二维码优先留给 PPT 文字层后期排版。
- **视频**：把文字转成镜头清单、分镜画面、角色动作和字幕建议；保持同一角色外观、服装识别色和镜头连续性。
- **推文/赛事介绍**：从长文中筛选 1–3 个认知锚点，生成图文并茂、可直接阅读的配图。

不同载体的版式和动效规则见 `references/platform-recipes.md`；需要视频或网页动效时，再读取 `references/video-storyboard.md`。

调用时优先说明目标载体（网页 / PPT / 视频 / 推文）、画面比例、需要保留的文字和是否需要直接生成。

## 目标

把用户提供的任意文字、工作流、规则、方法论、活动说明或聊天记录，先提炼出关键文字和结构，再转换为一张图文并茂、可读、可视化的手绘解析图。默认 16:9；用户要手机海报、今日战报或社交媒体长图时改用 9:16。使用赛事女孩作为固定视觉 IP，替换原 Ian Skill 中的小黑角色；保留原 Skill 的文字提取、概念可视化、构图、原创隐喻、单图单核心和 QA 逻辑。

这不是主 KV、商业海报、课程 PPT 或证券 App 截图生成器。涉及 Logo、主标题、赛事日期、奖项和二维码时，生成无文字角色/场景底图，再用正式物料后期排版。

## 工作流程

### 1. 读取并提炼文字

读取用户提供的推文、文章、网页文案、赛事规则、任务卡、截图或主题。自动提炼：

- 核心判断或认知转折
- 适合视觉化的段落
- 角色应承担的动作
- 必须后期排版的官方文字、Logo、日期、数字和二维码

还要提取：

- 一个能概括整张图的标题
- 3–6 个关键步骤、角色、节点或结论
- 每个节点下 1–2 行简洁解释
- 节点之间的顺序、因果、分工或前后关系
- 需要突出显示的风险、结果、条件和下一步

不要平均给每段配图，也不要把所有文字删掉。优先选择报名路径、比赛阶段、研究方法、风险意识、行情复盘、任务闭环、学生状态变化和权益路径等认知锚点。

### 2. 先输出图文结构草案

在生图前，先确定准备放进图片的文字结构：

- 图内标题
- 3–6 个区块或步骤
- 每个区块的短说明
- 角色、箭头、卡片、框、时间线或隐喻物件
- 中英文固定词的准确拼写

如果用户只要求图片，可以把这份草案简短呈现后继续生成，不要因为草案而停住。

### 3. 先输出 shot list

用户只要求规划时，先输出 4–8 张 shot list；短文输出 1–3 张。每张写清：放置位置、主题、核心意思、结构类型、赛事女孩的动作、元素和建议短标注。

### 4. 单张生成

用户明确要求生成时，每张图单独调用图像模型。默认使用 `references/prompt-template.md`，并参考 `01-canonical-full-body.png`；涉及研究行情时参考 `02-market-research.png`，涉及报名或赛事引导时参考 `03-event-guide.png`。

每张图必须满足：默认 16:9 横版；9:16 时保持同一笔触并改为上下分段；纯白背景、黑色手绘线稿、轻微手绘抖动、可爱但不幼稚的角色比例、标题和关键文字清楚可读、深蓝和青色克制使用、少量红橙蓝中英文标注、赛事女孩参与核心动作、只表达一个核心结构。不要把 9:16 机械拉伸成横图。

需要使用 Imagen 时，先用角色参考图控制人物一致性，再生成动作或无文字场景；需要逐字准确的中文、数字、日期、金额、Logo、链接和二维码时，优先用 PPT/HTML/SVG 文字层叠加，不让模型猜写长文本。若用户明确要求“图内文字也由 Imagen 完成”，只保留短标题、3–6 个短标签和短句，并在生成后逐字 QA。

禁止出现：小黑、其他 IP 角色、主 KV 式蓝色光效背景、复杂证券 App UI、未经提供的 Logo、大段密文或整页正文、错误奖项数字、左上角类型标题、PPT 网格、正式流程图、渐变、噪点、米色纸张、商业海报感。

### 文字与概念可视化

支持在图中使用正常可读的中文或英文文字，包括标题、步骤名、角色名、短句、气泡、卡片说明和结论。例如“结营后，下一步怎么跟进？”、“项目老师”“销售老师（CC）”“Research”“Risk”“Review”。优先从用户原文提取和压缩，不要凭空编造。

标题和关键说明可以直接放在图里；生成时必须明确要求“正常可读的中文/英文手写文字，不要乱码，不要伪文字”。如果文字非常长、包含大量数字或必须逐字准确，再保留排版区域并额外提供文字层版本。图像模型负责把“研究、筛选、风险、路径、复盘”等抽象概念画成可理解的动作、物件和关系。

### 4. 资产分层

按用途分层输出：

- 角色资产：透明底或纯白底单人 PNG，供网页、PPT、推文再次排版。
- 正文插图：16:9 白底图文解析图，包含标题、步骤、短说明和可视化动作，不放官方 Logo。
- 页面场景底图：为网页模块、赛事介绍页提供无标题留白底图。
- 官方组合物料：只在用户明确要求时把正式 Logo、标题、日期和二维码交给后期排版，不让图像模型重绘。

### 5. 生成后 QA

读取 `references/qa-checklist.md`。不符合时重生成或局部编辑。优先修正人物漂移、错误手部、背景光效、中文字错、画面过满和角色只站旁边的问题。

### 6. 保存

在赛事项目 workspace 中，把正文配图保存到：

```text
assets/<article-slug>-illustrations/
```

角色母版和动作参考保存在 Skill 的 `assets/character-reference/`。按 `01-`、`02-` 顺序命名，不覆盖已有资产，除非用户明确要求替换。

## 交付口径

生成后说明生成数量、每张用途、保存路径，以及是否需要后期叠加 Logo、赛事文字或二维码。不要把未经校验的金融数字或证券名称直接写进图里。

## 跨工具调用口径

- **PPT/海报**：先给出图文结构草案，再生成角色或插图；正式文字、数字和品牌元素留在可编辑文字层。
- **网页**：返回图片资源、alt 文案、建议插入位置和响应式尺寸；9:16 素材不得被 CSS 拉伸变形。
- **视频**：先给出 4–8 镜头 shot list，再生成关键帧；用轻微平移、手绘箭头生长、K 线逐笔出现、卡片翻页等动效，不把静态插图改成霓虹赛博风。
- **DeepSeek Harness / WorkBuddy / 豆包**：把本目录作为 Skill 根目录，入口始终是 `SKILL.md`；工具若不能读取二进制参考图，则读取 `references/style-dna.md`、`references/xiaohei-ip.md` 和 `references/recovered-webbook-catalog.md`，仍必须遵守同一角色和画风规则。
